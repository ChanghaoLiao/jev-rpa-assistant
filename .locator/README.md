# 录制聊天页面的五个位置

从 Jev 的“平台与录制”点击“开始录制”，使用程序打开的 VS Code 项目。录制文件保存在当前用户数据目录的 `.locator` 内；不要保存到安装目录。Store 名称以页面提示为准，也支持其他合法名称。

| 名称 | 录制目标 |
|---|---|
| `new_message` | 带红点的完整客户行，包含头像和昵称；不是单独红点或整个消息列表 |
| `current_user` | 右侧当前客户的完整名字；切换客户后能读取新的名字 |
| `chat_window` | 右侧聊天内容区域，不含消息输入框 |
| `reply_text` | 可输入并读回完整文字的回复输入框 |
| `button_send` | 当前会话的发送按钮，必须唯一 |

## 闲鱼网页版＋Edge

五项保存后回到程序，点击“录制完成，自动整理并检查”。程序备份录制库，在隔离副本中整理 `new_message` 的网页条件，去除固定昵称、序号、未读数字和悬停限制，保留浏览器及标签页约束。其他四个定位器不改。

`new_message` 不要求先手动修改属性或通过录制器的 Validate；程序会核对它只匹配当前消息列表内带未读标记的客户行。其他四项仍需能唯一匹配并读到正确内容。只保留一个用于验证的闲鱼聊天标签页，并手动打开一条会话。没有未读时显示等待验证，不代表规则失败。

规则整理和未读变化验收分开：先记录当前未读会话数；选择原本已读的测试买家，让其发消息后再检查；手动读完再检查。应出现“增加、回到原数”。不需要清空其他客户的未读。测试消息、真实发送验收由用户操作。

## 其他平台

其他平台或浏览器尚未支持自动整理，继续使用原录制及人工验证方式。各平台需要分别适配，不能直接套用闲鱼网页规则，也不能仅修改验收标记来宣称通过。

如果多个库完整，程序会让你选择；缺项则显示具体原因。共享给其他账号的库不会直接修改。检查期间重新保存、取消或文件被占用时，不覆盖录制原件。

程序显示“录制库已接入、规则已整理、页面匹配通过、未读变化已验收”四个独立阶段。页面检查不发送、不调用模型；找到元素不能代替真实接待验收。
