# 架构与调用链

## 启动和调度

```text
app.py
  └─ jevtool/gui.py                 兼容入口
       └─ controller.py / views.py  界面状态和按钮
            └─ worker.py           一个后台线程、一条任务队列
                 └─ service.py     组织监测、识字、选话术与发送
```

入口负责启动，Worker 负责串行调度，Service 负责具体业务顺序。
界面提交任务、接收事件；耗时操作在 Worker 中执行，停止信号在步骤间检查。
这不限制用户手动切换页面或其他进程操作同一聊天页。

## 模块分工

| 文件 | 职责 |

| `web_messages.py` | 解析网页消息序列，核对新增卖家回复 |
| `vision.py` | 视觉请求、结构化消息解析、待答客户消息提取 |
| `router.py` / `knowledge.py` | 当前层 Choice、分类树、话术条件与最终复核 |
| `acceptance.py` / `acceptance_view.py` | 三段接待验收及续接 |

## 两种监测入口

每轮最多处理一个会话。当前会话与未读列表交替优先，没有新任务时检查另一入口。
当前会话先读取客户、内容摘要、草稿和滚动状态，不变时不截图、不调用模型。
内容连续两轮一致后才确认新变化，再进入共用快照处理。
首次观察只建立基线；已处理消息继续受数据库去重约束。

## Jev 分层选择

```text
客户待答消息＋可见历史
  → 根目录的类别选项＋HUMAN
  → 选中类别的子类别＋HUMAN
  → 当前叶层的话术条件、正文＋HUMAN
  → 对选中话术做 SEND／HUMAN 复核
  → 候选或人工处理
```

每次只发送当前层选项，不一次灌入全部话术；`categories.json` 提供类别说明。
`when_to_use`、`when_not_to_use` 和固定原文参与选话术。
响应选项、概率结构和数值范围仍会校验；旧数值门槛字段保留配置兼容，但不再作为额外拦截门槛。
`SEND` 是模型复核选项，并不直接点击发送。

## 发送与确认

1. 核对客户、最新位置、消息和截图状态。
2. 输入框须为空；粘贴后读回并再次核对。
3. 闲鱼发送前保存网页消息序列。
4. 先持久化点击意图，再调用发送按钮；日志失败则不点击。
5. 闲鱼在限定时间内只读轮询，连续两次序列稳定后核对新增卖家气泡。
6. 允许卖家回复后已有买家追问；留给下一轮，不能拿历史同文回复代替成功。
7. 不能唯一确认时记录未知并暂停客户，不自动补发。

其他平台仍走各自已有流程，不能据闲鱼代码推断全部平台均能网页核对。
